# The demo city

The sandbox is filled so the app can be looked at as a working product rather
than as a set of empty states. This is what is in it, where it came from, and
how to take it back out.

**Everything below is invented.** No business, event, job, review, deal or
notice describes anything real. Nothing may be shown to residents as if it did.

## Where it lives

| Thing | Where |
|---|---|
| The drawings | `public/art/*.svg`, generated by `scripts/generate-demo-art.mjs` |
| The list of drawings | `src/lib/demo-art-manifest.ts`, generated with them |
| The data | `supabase/seeds/demo_city_*.sql`, applied to sandbox `waezoxzkvhuqjzomafee` |

Production (`nnepslwwqjxfhlurwoyw`) was not touched.

## The pictures

There are no photographs, and a city of gray boxes reads as broken software
rather than as a place. So every seeded thing gets a drawing: a flat scene in
the lokal palette, built from shared primitives so ninety six pictures look
like one set. Storefronts vary their width, roofline, sign style, awning and
time of day from a hash of the key, which is what stops a list of shops from
looking like one building recoloured.

Three kinds:

- **Scenes** at 3 by 2, cropped to 16 by 9 on cards and 4 by 3 on heroes.
  Everything that matters is kept inside the band both crops keep.
- **Logo marks** at 1 by 1, because a cropped storefront turns to mush in a
  40 pixel circle.
- **Avatars**, deliberately silhouettes. A demo resident is not a real person
  and inventing a face would be a lie the size of the avatar.

Regenerate with `node scripts/generate-demo-art.mjs`. It is deterministic, so
a rerun produces no diff unless the script changed. The whole set is on
`/dev/kit`, cropped the way a card crops it.

Rows point at a drawing two ways:

- The existing `cover_image_url`, `image_url`, `logo_url` and `photo_url`
  columns hold a root relative path like `/art/cafe-coffee.svg`, so every
  screen that already reads those columns shows a picture with no change.
- `entity_media.bundled_key` holds the bare key, like `cafe-coffee`, resolved
  by `artUrl()` in `src/lib/bundled-art.ts`. Keyed to `city_entities`, so one
  table gives pictures to neighbourhoods, parcels, jobs and issues at once.

One code change was needed for the first of those: `isStoragePath()` in
`src/lib/image-cache.ts` treated `/art/cafe.svg` as a Supabase storage path and
tried to sign it, which silently fell back to the placeholder. A root relative
URL is now recognised as an app asset and used as it is.

## What was seeded

| Seed | What it adds |
|---|---|
| `demo_city_01_people.sql` | 10 demo residents, so reviews and stories have authors |
| `demo_city_02_businesses.sql` | 38 more businesses (50 total), plus pictures, hours, slugs and locations for the 12 that were already here |
| `demo_city_03_events.sql` | 40 events across ten weeks, and the 10 existing ones moved onto the coming fortnight |
| `demo_city_04_deals_jobs.sql` | 20 deals and 22 job posts |
| `demo_city_05_reviews.sql` | 184 reviews, then `average_rating` and `review_count` recomputed |
| `demo_city_06_community.sql` | 6 more nonprofits, 8 stories, 5 tours with 15 stops, 5 challenges, 6 programs |
| `demo_city_07_pulse_and_drop.sql` | 24 pulse posts, a published daily drop for today and the six days before, city signals, neighbourhood energy |
| `demo_city_08_city_life.sql` | Food truck stops for the week, 12 more issues, city memories, impact numbers, B2B requests, change log notices |
| `demo_city_09_pictures.sql` | `entity_media`: a hero for all 494 entities, 62 logos, 213 gallery photos |

Every seed is idempotent. Ids are fixed or derived from a hash, and every
insert is guarded, so running one twice inserts nothing.

Dates are written as offsets from `current_date`, not as fixed dates, so the
calendar is full of upcoming things whenever the seed is run rather than a list
that expired the week it was written. The daily drop falls back to the most
recent published one, so the Today tab stays filled as days pass.

## The demo residents

Ten accounts on the reserved `.invalid` domain, so no address can ever reach a
real inbox. They carry no password: the `auth.users` rows were inserted without
`encrypted_password`, so every sign in attempt is refused. They exist only to
be the author of a review, a story or a pulse post.

Reviewer names do not show to a signed out visitor. `profiles` is behind a
policy that requires authentication, which is the app's own privacy decision,
so `ReviewCard` falls back to "Anonymous". A signed in viewer sees the names.
That is existing behaviour, not something these seeds changed.

## Taking it out

```sql
-- The people, and everything of theirs that cascades.
delete from auth.users where email like '%@demo.toledolokal.invalid';

-- The rows keyed on a demo uuid prefix.
delete from public.businesses  where id::text like 'd3110001-%';
delete from public.events      where id::text like 'd3110003-%';
delete from public.deals       where id::text like 'd3110004-d004%';
delete from public.jobs        where id::text like 'd3110004-a004%';
delete from public.nonprofits  where id::text like 'd3110006-c006%';
delete from public.tours       where id::text like 'd3110006-70a6%';
delete from public.challenges  where id::text like 'd3110006-c4a1%';
delete from public.programs    where id::text like 'd3110006-9106%';
delete from public.pulse_posts where id::text like 'd3110007-%';
delete from public.issues      where id::text like 'd3110008-%';

-- The pictures, which are all bundled art rather than uploads.
delete from public.entity_media where bundled_key is not null;
```

The twelve original businesses and ten original events are updates rather than
inserts, so removing the seeds leaves them in place with their new pictures and
hours. Setting `cover_image_url` back to null is a separate decision.

## Known gaps

- **The Loop is not seeded.** `LP_ENABLED` is off by default, so the wallet,
  missions and rewards screens are unreachable. Seeding them would fill tables
  nobody can see.
- **No follows, saved items or check ins.** Those are per user rows and the
  demo accounts cannot sign in, so they would show to nobody.
- **Reviews are anonymous when signed out**, as described above.
